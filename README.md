# socials

Особистий пайплайн автоматизації відео: Telegram-бот приймає відео → вирізає тишу → генерує субтитри → накладає субтитри на відео → робить кастомну обкладинку → завантажує в S3 → публікує в TikTok (3 рази на день за розкладом, у чернетки — власник публікує вручну). Далі `/publish_ig` показує список чернеток з РЕАЛЬНИМИ переглядами (якщо відео вже опубліковане в TikTok вручну) — власник сам обирає, яке відео републікувати як Instagram Reels.

Другий сценарій: сторітейл-каруселі. Слайди готуються заздалегідь (напр. в Claude Desktop) і надсилаються боту одним альбомом фото — бот вивантажує їх у S3, питає підпис і час публікації, і публікує каруселлю в Instagram Graph API автоматично за розкладом.

## Архітектура

```
main.py                  Telegram-бот (прийом відео/фото, команди /start /status /queue /publish_ig /nocap)
config.py                Завантаження конфігурації з .env
db.py                     SQLite: відео, каруселі, черга публікацій

pipeline/
  ffmpeg_processor.py     Вирізання тиші, накладання субтитрів (FFmpeg)
  transcriber.py          Whisper / AssemblyAI → .srt
  cover_generator.py      Кастомна обкладинка (Pillow)
  uploader.py             Завантаження файлів у S3 (відео, обкладинки, слайди каруселей)

publishers/
  tiktok.py                Публікація в TikTok (чернетки), video.list — реальні перегляди публічних відео
  instagram.py             Публікація Reels + каруселей (сторітейлів) в Instagram

scheduler/
  queue_runner.py          Черга публікацій: tiktok / instagram (Reels) / instagram_carousel — за розкладом
  cron_checker.py           ЗАСТАРІЛО, деактивовано (див. коментар у файлі) — заміна: /publish_ig

webapp/                    Сторінки Terms/Privacy + TikTok/Instagram OAuth (Login Kit / Business Login)
```

## Сторітейл-каруселі в Instagram

1. Підготуй слайди (готові зображення з текстом, напр. в Claude Desktop) і надішли їх боту в Telegram **одним альбомом** (вибрати кілька фото одразу — Telegram групує їх в один `media_group`). Мінімум 2, максимум 10 слайдів.
2. Бот вивантажує слайди на S3 і просить підпис — надішли текстом, або `/nocap` щоб опублікувати без підпису.
3. Обери час публікації (кнопки, як для TikTok) — карусель автоматично опублікується в Instagram Graph API у заданий час, без додаткового підтвердження.

## /publish_ig: реальні перегляди TikTok

TikTok без App Review дозволяє лише "чернетки" (inbox) — власник сам публікує відео в застосунку. Бот не може автоматично знати, що вибухнуло. Натомість `/publish_ig`:
1. Підтягує список уже ПУБЛІЧНИХ відео акаунта через `video.list` (реальні перегляди).
2. Зіставляє їх із чернетками в БД за найближчим часом публікації (найкраще наближення без спільного ID).
3. Показує кнопки з реальними переглядами (👁), відсортовані від найбільшого — вибір, яке саме публікувати в Instagram Reels, завжди за власником.

Якщо `video.list` ще не авторизований — треба заново пройти `/auth/tiktok/login` (scope оновлено, див. нижче).

## Налаштування

1. Встановити залежності (рекомендовано Miniforge, якщо немає прав адміністратора на Mac):
   ```
   pip install -r requirements.txt
   ```
2. Скопіювати `.env.example` у `.env` і заповнити всі значення (Telegram токен, OpenAI/AssemblyAI ключ, S3, TikTok, Instagram).
3. Запуск локально:
   ```
   python main.py
   ```

## TikTok: отримання access_token через Login Kit (OAuth)

Замість того щоб вручну копіювати `TIKTOK_ACCESS_TOKEN`, можна один раз пройти авторизацію
у браузері й застосунок сам збереже токен (і сам оновлюватиме його через `refresh_token`):

1. У `.env` / Railway Variables задати `TIKTOK_CLIENT_KEY`, `TIKTOK_CLIENT_SECRET`,
   `TIKTOK_REDIRECT_URI` (= `https://<твій-railway-домен>/auth/tiktok/callback`),
   а також `ADMIN_SECRET` і `FLASK_SECRET_KEY` (будь-які довгі випадкові рядки).
2. У TikTok Developer Portal у Login Kit вказати точно той самий redirect URI.
3. Відкрити в браузері:
   `https://<твій-railway-домен>/auth/tiktok/login?key=<твій ADMIN_SECRET>`
4. Залогінитись своїм TikTok-акаунтом і підтвердити доступ — токен збережеться в БД автоматично.

`TIKTOK_ACCESS_TOKEN` / `TIKTOK_OPEN_ID` з `.env` лишаються як fallback, якщо OAuth ще не пройдено.

**Важливо:** scope тепер включає `video.list` (для реальних переглядів у `/publish_ig`, див. вище). Якщо TikTok вже був підключений раніше (до цієї зміни) — токен ще не має цього дозволу, треба **заново** пройти `/auth/tiktok/login`, інакше `video.list` повертатиме помилку scope.

## Деплой на Railway

Конфігурація вже є в `railway.toml` і `Procfile`:
- сервіс `bot` — Telegram-бот, працює постійно
- сервіс `cron-checker` — щоденна перевірка найкращого відео (крон)

Усі значення з `.env` потрібно додати в Railway → Variables.

## Безпека

`.env` з реальними токенами та `*.db` файли виключені через `.gitignore` і ніколи не потрапляють у git.
